# ML

Описание модели оценки качества укладки DXA-исследования. Проверка выполняется локальным HTTP-сервисом.

Формат результата, который принимает система: [../product/results.md](../product/results.md). Границы: [../product/limitations.md](../product/limitations.md).

Оглавление: [../README.md](../README.md).

## Назначение

Сервис читает один DICOM и возвращает область, класс качества и типы нарушений. Веса лежат в `ml/models/` и загружаются один раз при старте процесса.

## Входные данные

ML получает сам файл по HTTP. Общий каталог с API не нужен, путь к файлу на диске Backend не передаётся.

`POST /analyze`

`Content-Type: multipart/form-data`, поле `file` — DICOM.

Ответ — JSON. Рядом с клиническими полями сервис отдаёт `study_uid`, `image_uid`, `time_of_processing` и `processing_status`. Поля `quality_prob` в ответе нет.

Проверка сервиса: `GET /health`.

## Предобработка

Область выбирается по ширине кадра: 300 столбцов — поясничный отдел, 280 — бедро. Иная ширина относится к ближайшей из двух.

Дальше пиксели приводятся к uint8 через min-max, кадр меняет размер до 320×320, канал повторяется три раза и применяется нормализация ImageNet.

У позвоночника в min-max есть слагаемое `1e-6`. У бедра его нет: в сеть попадает тот же uint8, что после первого min-max.

Сеть укладки бедра по изображению получает только этот тензор. Hybrid-сеть получает его же и геометрические признаки кадра.

## Модель

Позвоночник — ансамбль из пяти ResNet18, файлы `spine_cnn_fold0.pt` … `spine_cnn_fold4.pt`. Два выхода: укладка и посторонние предметы. Ось — логистическая регрессия `spine_axis_model.joblib` по углу яркой средней линии.

Пороги `spine_lay`, `spine_obj` и `spine_axis` читаются из `thresholds.json`.

Бедро — ансамбль двух сетей по пять фолдов в `femur_lay_sideaware_v5_final/`: `image_only_fold0.pt` … `fold4.pt` и `hybrid_fold0.pt` … `fold4.pt`. Оценка укладки — смесь 0,7 image-only и 0,3 hybrid. С порогом сравнивается эта смесь. Порог задан в коде и равен `0.193505`. Значение `femur_lay` в `thresholds.json` не используется.

Область интереса бедра — правило по высоте кадра, отдельной сети для неё нет.

## Обучение

Кратко по ноутбукам `ml/notebooks/spine_pipeline.ipynb` и `ml/notebooks/femur_lay.ipynb`.

Обучение использует разметку организатора. Поясничный отдел берёт метки из `НД_для_обучения/разметка.xlsx`. Укладка бедра берёт метки из таблицы, подготовленной по этой разметке.

Оба ноутбука делят данные на 5 фолдов `StratifiedGroupKFold`. Группа — `study_id`. Image-only и hybrid бедра учатся на одних и тех же фолдах.

Веса, которые читает сервис, лежат в `ml/models/`.

## Инференс

`POST /analyze`: DICOM, предобработка, модели выбранной области, затем класс, область и нарушения.

Позвоночник: средний ответ пяти сетей и вероятность оси. Бедро: смесь image-only и hybrid, затем проверка высоты кадра.

## Формат результата

| Поле | Смысл |
| --- | --- |
| `quality_class` | `0` — нарушений нет, `1` — нарушение есть |
| `violation_type` | типы через `;`, либо пустая строка |
| `anatomical_region` | «Поясничный отдел позвоночника» или «Проксимальный отдел бедра» |

Поясничный отдел: «Некорректная укладка», «Не выравнена ось позвоночника», «Присутствуют посторонние предметы».

Бедро: «Некорректная укладка», «Некорректная область интереса».

Класс `0` идёт с пустым списком. Класс `1` — хотя бы с одним типом своей области.

## Тепловая карта

ML строит PNG и кладёт его в JSON как base64, поле `heatmap_png`. В каталог загрузок API сервис не пишет.

Backend декодирует поле и сохраняет `heatmap.png` рядом со своим DICOM. Если карты нет, текстовый результат всё равно возвращается.

## Ограничения

Угол оси считает модель по яркой средней линии. Сравнения с фиксированными 5 градусами нет.

«Некорректная область интереса» — короткая высота кадра, не поля 3 см и 2 см вокруг большого вертела.

Сторона бедра и внутренние scores в ответ API не входят. Метрики качества модели в этом описании не приводятся.
