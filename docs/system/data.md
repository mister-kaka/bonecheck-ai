# Хранение данных

Система хранит исследования и результаты их проверки. История - это список этих исследований.

Оглавление: [README.md](../README.md). Устройство системы: [architecture.md](architecture.md).

Раздел «Мои» показывает записи браузера, из которого файл был загружен. Раздел «Все» показывает весь список.

## Исследование

Одна запись - один DICOM.

| Данные | Зачем |
| --- | --- |
| Идентификатор | UUID v4, по нему открываются статус, результат и снимок |
| Сессия | чей браузер загрузил файл; пусто, если сессия не передана |
| Статус | файл принят, идёт анализ, готово, ошибка анализа |
| Имя файла | как его видит пользователь |
| Даты создания и обновления | журнал и сортировка |
| Текст ошибки | если проверка не выполнена |
| Файл DICOM | на диске, не внутри записи метаданных |

Статусы в интерфейсе:

| Статус в данных | Подпись |
| --- | --- |
| `uploaded` | Файл принят |
| `processing` | Идёт анализ |
| `completed` | Готово |
| `error` | Ошибка анализа |

После загрузки статус - «Идёт анализ».

## Результат

Результат хранится в той же записи исследования.

| Поле | Когда заполнено |
| --- | --- |
| `quality_class` | 0 или 1 у готового исследования |
| `violation_type` | строка нарушений, в том числе пустая, если нарушений нет |
| `anatomical_region` | одна из двух областей |
| `quality_prob` | число от 0 до 1, если оно есть в результате |

Пока анализ идёт или завершился ошибкой, этих полей нет. Пустая строка нарушений означает «нарушений нет». Отсутствие результата - это не пустая строка, а отсутствие полей.

`hasResult` в статусе исследования вычисляется: статус «Готово» и результат читается.

## История

Список сортируется по дате создания, сначала новые. При одинаковом времени порядок определяется идентификатором.

- с `session_id` - исследования этого браузера;
- без `session_id` - все исследования.

Исследование без сессии видно только в «Все». После перезапуска API те же записи и тот же идентификатор сессии находятся снова.

Поиск, область, исход, даты и страницы в хранилище не записываются. Их считает интерфейс.

## Где лежат данные

| Что | Где |
| --- | --- |
| Метаданные | файл SQLite, переменная `DATABASE_PATH` |
| Локально, если переменная не задана | `data/bonecheck.sqlite` относительно каталога запуска API |
| В Docker | `/app/data/bonecheck-docker.sqlite`, каталог `backend/data` на машине |
| DICOM | `UPLOAD_DIR/<id>/<имя файла>` |
| Тепловая карта | `UPLOAD_DIR/<id>/heatmap.png`, если ML смог её записать |
| Локально, если переменная не задана | `uploads/` относительно каталога запуска API |
| В Docker | `/app/uploads`, каталог `backend/uploads` на машине |

Каталог и таблица создаются при старте API. Повторный запуск данные не удаляет.

Файлы исследований остаются после «Готово» и после «Ошибка анализа».

Чтобы начать с пустой истории, нужно остановить API и удалить файл базы. Загруженные DICOM при этом остаются в каталоге `uploads`, пока его не очистят отдельно.
