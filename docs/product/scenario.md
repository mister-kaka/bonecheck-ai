# Пользовательский сценарий

Путь от открытия системы до результата и истории.

Оглавление: [README.md](../README.md).

## 1. Открытие

Пользователь открывает интерфейс. В шапке два раздела: «Анализ» и «История». Стартовый экран - «Проверка исследования».

На нём зона загрузки, краткие шаги «Как это работает» и список типов нарушений поясничного отдела.

## 2. Выбор файла

Пользователь перетаскивает файл в зону загрузки либо нажимает «Выбрать файл» или «Загрузить ZIP».

Принимается один DICOM или один ZIP. Папка и несколько файлов сразу не принимаются.

Если файл подходит, появляется экран «Файл выбран» с именем, размером и форматом. Дальше - «Начать проверку» или «Отмена».

## 3. Проверка входных данных

До отправки интерфейс проверяет расширение, пустой файл и размер 50 МБ. API повторяет эти проверки.

Неподходящий файл остаётся на экране с заголовком «Файл не принят». Исследование при этом не создаётся.

Правила файлов: [files.md](files.md).

## 4. Загрузка и анализ

После «Начать проверку» экран показывает ход: «Загрузка файла», затем «Анализ». На загрузке виден процент отправленного файла. На анализе полоса ждёт ответ сервера, процента нет.

«Прервать ожидание» останавливает только этот экран. Если файл уже принят, исследование остаётся в истории.

Если проверка длится дольше примерно трёх минут, появляется экран «Анализ ещё выполняется». Можно нажать «Продолжить ожидание» или «Открыть в истории».

## 5. Результат одного снимка

Один DICOM и ZIP с одним DICOM открывают результат на том же экране «Анализ».

Пользователь видит:

- «Укладка корректна» или «Нарушение качества укладки»;
- имя файла;
- анатомическую область;
- вероятность нарушения, если она есть в результате;
- обнаруженные нарушения;
- критерии этой области: «Нарушение» или «Без нарушений»;
- снимок.

Действия: «Экспорт», «Открыть в истории», «Новое исследование». В меню экспорта два пункта: «Журнал» и «Итоговый файл».

Как читать результат: [results.md](results.md).

## 6. Несколько снимков в ZIP

Если в архиве больше одного DICOM, после проверки открывается экран «Архив принят».

На нём имя архива, число созданных исследований, сколько уже готово, и список файлов. У каждой строки статус. У готовой проверки рядом стоит «Без нарушений» или «Нарушение качества укладки». Нажатие на строку открывает карточку этого снимка.

Итог показывается по каждому снимку отдельно.

## 7. Снимок

Рядом с результатом показывается изображение. Можно увеличить, уменьшить, сдвинуть и вернуть исходный масштаб. Колёсико мыши меняет масштаб.

Снимок одного DICOM, выбранного на экране «Анализ», берётся из файла пользователя. Снимок из архива и снимок в карточке истории запрашиваются у системы по исследованию.

## 8. История

Раздел «История» открывает «Историю исследований».

- «Мои» - загрузки этого браузера;
- «Все» - общая история;

В таблице: дата, файл, анатомическая область, статус, нарушение. Строка открывает карточку.

Поиск, фильтры, сортировка и страницы применяются к уже загруженному списку. Пока исследование в статусе «Идёт анализ», строка обновляется.

## 9. Карточка и экспорт

Карточка показывает статус, результат и снимок. Кнопка «К истории» возвращает к журналу с теми же фильтрами.

«Экспорт» на результате готовит файл этого исследования. В карточке «Экспорт XLSX» скачивает журнал этой записи. «Экспорт» в истории берёт текущую отфильтрованную выборку. «Журнал» - дата, область и результат словами. «Итоговый файл» - класс качества, нарушения и время обработки. Пустая история без сужающих фильтров скачивает файл только с заголовками колонок.

## Если проверка не удалась

Экран «Проверка не выполнена» показывает текст ошибки. Кнопка «Загрузить другой файл» возвращает к выбору файла. В карточке при ошибке анализа кнопка ведёт к загрузке.

Исследование с ошибкой остаётся в истории со статусом «Ошибка анализа».

Дальше: [результат анализа](results.md).
