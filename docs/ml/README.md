# ML

Каталог проверки укладки DXA. Модуль смотрит один снимок и возвращает класс качества, область и типы нарушений. Диагноз, T-score и минеральную плотность он не считает.

Архитектура, обучение и метрики сюда не входят. Они пишутся отдельно в [docs/ml/README.md](../docs/ml/README.md). Формат, который уже принимает API: [результат анализа](../docs/product/results.md).

## Что вызывает сайт

Модели загружаются один раз при старте процесса. На каждый DICOM два вызова и ничего больше.

```python
from inference.pipeline import load_models, site_prediction, save_heatmap_png

load_models()  # в контейнере это /app/models, переменная MODEL_DIR
result = site_prediction(dicom_path)
save_heatmap_png(dicom_path, heatmap_path)
```

`predict_single_dicom` и `process_directory` отдают широкую строку отчёта для сдачи, не карточку исследования. `visualize_dicom` открывает окно matplotlib.

## Вход

Один файл `.dcm`. Область берётся по ширине кадра, не по имени файла: 300 столбцов - поясничный отдел, 280 - проксимальное бедро. Суффиксы `ПОП`, `ППОБ`, `ЛПОБ` в проверке не участвуют.

Сторона бедра в ответ не входит. Если она не определилась, счёт укладки считается по исходному кадру и по горизонтальному отражению, затем усредняется.

## Выход

`site_prediction` возвращает только эти три поля.

```json
{
  "quality_class": 1,
  "violation_type": "Некорректная укладка;Не выравнена ось позвоночника",
  "anatomical_region": "Поясничный отдел позвоночника"
}
```

`quality_class` - целое `0` или `1`. При `0` поле `violation_type` пустое. При `1` типы этой области записаны через `;` без пробела, без пустых кусков и без повторов.

Позвоночник:

- `Некорректная укладка`
- `Не выравнена ось позвоночника`
- `Присутствуют посторонние предметы`

Бедро:

- `Некорректная укладка`
- `Некорректная область интереса`

`anatomical_region` - ровно `Поясничный отдел позвоночника` или `Проксимальный отдел бедра`.

Тепловая карта - отдельный PNG исходного размера и исходной лево-правой ориентации. На карте только укладка. Ось, посторонние предметы и область интереса цветом не выделяются. Левое бедро для сети отражается и перед записью PNG возвращается обратно. Если PNG не записался, текстовый результат всё равно сохраняется.

## Веса

Они лежат в `models/` и уже в git. Образ копирует эту папку в `/app/models`.
Нужны ровно эти файлы:

- `thresholds.json`
- `spine_axis_model.joblib`
- `spine_cnn_fold0.pt` … `spine_cnn_fold4.pt`
- `femur_lay_sideaware_v5_final/image_only_fold0.pt` … `fold4.pt`
- `femur_lay_sideaware_v5_final/hybrid_fold0.pt` … `fold4.pt`

Имя папки бедра не менять.

Порог укладки бедра зашит в коде: смесь `0.7 * image + 0.3 * hybrid`, порог `0.193505`. Рабочие значения: укладка `0.7592255473136902`, посторонние предметы `0.4454249441623688`, ось `0.592567792815834`.

## Что делает проверка

Позвоночник: две головы одной сети (укладка и посторонние предметы) и отдельно угол оси от вертикали снимка, логистическая регрессия по одному числу. Ось идёт по центрам тел позвонков, не по остистым отросткам. Сколиоз отдельным типом не является.

Бедро: ансамбль на укладку и ротацию. «Некорректная область интереса» - не сеть и не рамка денситометра. Нарушение ставится, когда высота кадра `Rows <= 210` (`height_mm <= 220.5`).

Эндопротез, перелом и люмбализация в типы нарушений не входят.

## Ограничения

Обучающая выборка маленькая, и этим определяется потолок. После отбора одного кадра на сторону у бедра 34 положительных снимка в 23 исследованиях. У позвоночника после схлопывания до одного кадра на исследование положительных укладок шесть.

На процессоре один снимок занимает секунды: ответ быстрее, тепловая карта дольше.
