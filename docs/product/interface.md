# Интерфейс

Экраны загрузки, результата, истории и просмотра снимка.

Два раздела в шапке: «Анализ» и «История». Название продукта в шапке - BoneCheck AI, подпись - «Качество укладки DXA».

Оглавление: [README.md](../README.md). Сценарий: [scenario.md](scenario.md).

Рядом с разделами постоянно виден текст: «Проверка качества укладки. Не диагноз и не измерение минеральной плотности.»

Неизвестный адрес открывает «Анализ».

## Анализ

Адрес: `/`

Назначение: загрузить исследование и получить результат.

На старте пользователь видит заголовок «Проверка исследования», зону «Загрузите DICOM или ZIP», кнопки «Выбрать файл» и «Загрузить ZIP», подсказку про один файл до 50 МБ, блок «Как это работает» и блок «Типы нарушений» для поясничного отдела.

Дальше экран сменяется по ходу проверки. Отдельного адреса у этих состояний нет.

| Состояние | Что на экране | Действия |
| --- | --- | --- |
| Файл выбран | имя, размер, формат, «Можно начать проверку» | «Начать проверку», «Отмена» |
| Загрузка | процент отправки, блок «Ход проверки» | «Прервать ожидание» |
| Анализ | «Проверка качества укладки», ожидание без процента | «Прервать ожидание» |
| Анализ ещё выполняется | проверка не закончилась за отведённое ожидание | «Продолжить ожидание», «Открыть в истории» |
| Результат | итог укладки, критерии, снимок | «Экспорт истории», «Скачать submission», «Открыть в истории», «Новое исследование» |
| Архив принят | список исследований из ZIP | открыть снимок, «К истории», «Новое исследование» |
| Файл не принят | причина отказа | «Загрузить другой файл» |
| Проверка не выполнена | причина ошибки анализа | «Загрузить другой файл» |

«Ход проверки» показывает три шага: «Загрузка файла», «Анализ», «Результат». Результат открывается на этом же экране.

## Просмотр снимка

Просмотр встроен в результат и в карточку. Отдельной страницы у него нет.

Доступны увеличение, уменьшение, сдвиг мышью и сброс масштаба. Масштаб меняется от 50% до 500%. Колёсико мыши увеличивает и уменьшает изображение. Текущий масштаб показан на снимке.

Вкладка «Тепловая карта» появляется, если для исследования есть PNG. Это готовое изображение с карты укладки. Контур и ключевые точки интерфейс не рисует. Если PNG нет, остаётся просмотр DICOM и текстовый результат.

Если изображение прочитать нельзя, на месте снимка остаётся пояснение. Проверка укладки при этом уже может быть завершена.

## История исследований

Адрес: `/history`

Назначение: журнал загруженных исследований.

Пользователь видит таблицу и фильтры. Колонки: «Дата», «Файл», «Анатомическая область», «Статус», «Нарушение».

Переключатель:

- «Мои» - загрузки этого браузера;
- «Все» - общая история.

Фильтры:

- имя файла;
- анатомическая область;
- результат: «Без нарушений», «Нарушение», «Идёт анализ», «Ошибка»;
- тип нарушения;
- дата с и дата по;
- сортировка «Сначала новые» или «Сначала старые».

Активные фильтры можно снять по одному или все сразу. На странице 5, 10 или 20 строк, по умолчанию 10. Внизу счётчик «Показано N из M».

Пустой журнал: «Вы ещё не загружали исследования.» или «Общая история пуста.» Пустой фильтр: «По выбранным фильтрам ничего не найдено».

«Экспорт истории» выгружает журнал текущей выборки. «Скачать submission» выгружает файл сдачи по тем же исследованиям: восемь колонок из ТЗ, без полей журнала. Если фильтр ничего не нашёл, выгрузка не начинается и показывается «По выбранным фильтрам нет исследований для выгрузки.»

Если список не загрузился, виден текст «Не удалось загрузить историю» и кнопка «Повторить».

Нажатие на строку открывает карточку.

## Карточка исследования

Адрес: `/history/:id`

Назначение: статус, результат и снимок одной записи. Заголовок страницы - имя файла, подпись - «Карточка исследования».

| Состояние | Что видит пользователь |
| --- | --- |
| Загрузка | «Загрузка исследования» |
| Файл принят | «Файл принят, проверка ещё не начата» |
| Идёт анализ | «Результат анализа ещё не готов.» Статус обновляется |
| Готово | тот же блок результата, что на экране анализа, и снимок |
| Ошибка анализа | «Проверка не выполнена», текст ошибки и кнопка «К загрузке» |
| Нет записи | «Исследование недоступно» и «Повторить» |

Кнопка «К истории» возвращает к журналу. «Новое исследование» открывает загрузку. «Экспорт истории» выгружает журнал этого исследования. «Скачать submission» выгружает файл сдачи по нему.

## Экспорт

«Экспорт истории» есть на результате, в карточке и в истории. Рядом «Скачать submission». Это разные файлы.

Журнал одного исследования называется `bonecheck-<имя>.xlsx`. Журнал списка - `bonecheck-history.xlsx`. Файл сдачи - `bonecheck-submission.xlsx`.

Колонки журнала: «Файл», «Дата», «Анатомическая область», «Результат», «Тип нарушения», «Вероятность нарушения», «Статус». Дата показана по Москве, в виде `дд.мм.гггг чч:мм`.

Колонки файла сдачи: `path_to_study`, `study_uid`, `image_uid`, `anatomical_region`, `quality_class`, `violation_type`, `processing_status`, `time_of_processing`.
