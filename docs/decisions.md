# Архитектурные решения

Формат: Decision / Reason. Решения фиксируются до реализации бизнес-логики, чтобы команда и эксперты видели границы системы.

---

## Decision

Используем монорепозиторий.

## Reason

Удобная разработка и простая проверка решения экспертами.

Один репозиторий содержит frontend, backend, ML и Docker. Эксперту достаточно одной инструкции запуска (`README.md` + `docker compose up`) без сборки нескольких репозиториев и согласования версий.

---

## Decision

Backend NestJS, ML Python.

## Reason

Разделение прикладного слоя и ML слоя.

NestJS закрывает REST, валидацию и документацию API. Python закрывает DICOM, компьютерное зрение и inference. Слои можно развивать независимо и деплоить разными контейнерами.

---

## Decision

Frontend не вызывает ML-сервис напрямую.

## Reason

Единая точка входа упрощает проверку, логирование и будущую авторизацию. UI остаётся тонким клиентом.

---

## Decision

На этапе каркаса нет БД, пользователей и auth.

## Reason

Целевая проверка хакатона — качество оценки DICOM, а не личный кабинет. Хранение сессий и пользователей усложнило бы воспроизведение решения без пользы для метрик.

---

## Decision

ML-сервис — отдельный контейнер, даже пока это placeholder.

## Reason

Контракт развёртывания должен совпадать с целевой архитектурой. Позже в контейнер добавятся веса и HTTP inference без перестройки Compose.

---

## Decision

Датасет, DICOM-файлы и веса моделей не входят в репозиторий.

## Reason

Медицинские данные и артефакты обучения нельзя смешивать с исходным кодом. Репозиторий должен оставаться публичным и лёгким для клонирования.

---

## Decision

OpenAPI публикуется на `/api/docs`.

## Reason

Экспертам и команде нужен живой контракт API без чтения исходников. Swagger — стандартный способ проверки REST-каркаса NestJS.

---

## Decision

Единица будущего inference — файл изображения, а не папка исследования.

## Reason

Правило организаторов: одна строка выходной таблицы = одно изображение. Backend и ML должны проектироваться вокруг file-level предсказания, даже если UI позже группирует снимки по study.
