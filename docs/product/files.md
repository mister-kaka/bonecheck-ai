# DICOM и ZIP

Единица проверки - одно изображение. Один DICOM создаёт одно исследование. ZIP создаёт отдельное исследование на каждый DICOM внутри.

Оглавление: [README.md](../README.md). Сценарий загрузки: [scenario.md](scenario.md).

## Какие файлы принимаются

| Что загружает пользователь | Куда попадает |
| --- | --- |
| Один `.dcm` или `.dicom` | `POST /api/studies` |
| Файл с типом `application/dicom` или `application/x-dicom` | тот же метод |
| Один `.zip` или тип `application/zip` / `application/x-zip-compressed` | `POST /api/studies/packages` |

Кнопка «Выбрать файл» принимает DICOM. Кнопка «Загрузить ZIP» принимает архив. Файл можно перетащить в зону загрузки.

Папка не принимается. Несколько файлов, брошенных сразу, не принимаются: нужно выбрать один DICOM или один ZIP.

## Ограничения

| Ограничение | Значение |
| --- | --- |
| Размер DICOM | до 50 МБ |
| Размер ZIP | до 50 МБ |
| Записей в архиве | не больше 30 |
| Суммарный объём DICOM после распаковки | до 200 МБ |
| Размер каждого файла внутри ZIP | до 50 МБ |
| Состав архива | только `.dcm` и `.dicom` |

Вложенные папки в ZIP допустимы. В имя исследования попадает имя файла без каталога.

Имена в архиве читаются как UTF-8, если у записи выставлен этот признак. Иначе байты имени читаются как CP866. Латинские имена при этом не меняются.

## Как обрабатывается DICOM

1. Интерфейс проверяет имя, тип, пустой файл и размер.
2. API повторяет проверку.
3. Файл сохраняется и создаётся исследование.
4. Ответ приходит сразу, со статусом «Идёт анализ».
5. Обработка завершается отдельно. Интерфейс обновляет статус.
6. Готовый результат и снимок открываются на экране.

Содержимое DICOM на приёме не разбирается: достаточно имени или типа файла. Если файл назван как DICOM, но изображение прочитать нельзя, исследование может быть создано, а просмотр покажет, что снимок открыть не удалось.

Просмотр показывает несжатый одноканальный снимок с глубиной 8 или 16 бит. Сжатый DICOM, многоканальное изображение и другая глубина в просмотрщике не открываются. На проверку укладки это ограничение просмотра не влияет: исследование всё равно создаётся.

## Как обрабатывается ZIP

Архив разбирается в памяти. Пути из архива не используются как пути на диске.

Каждый подходящий DICOM сохраняется как своё исследование и проверяется отдельно. ZIP с одним снимком показывает обычный результат. ZIP с несколькими снимками показывает список «Архив принят».

Служебные записи пропускаются и сами по себе архив не отклоняют:

- каталоги;
- `__MACOSX`;
- `.DS_Store`;
- `Thumbs.db`.

## Защита от некорректного архива

Пакет отклоняется целиком, исследование не создаётся, если:

- архив пустой;
- внутри нет DICOM;
- рядом с DICOM лежит файл другого типа;
- архив повреждён или сжатие не поддерживается;
- в имени есть `..` или абсолютный путь;
- два DICOM имеют одно и то же имя;
- записей больше 30;
- распакованный объём или отдельный файл больше лимита.

Так архив не может записать файл за пределами каталога загрузок и не может подменить одно исследование другим через повтор имени.

## Что видит пользователь при отказе

Заголовок: «Файл не принят». Текст приходит от проверки. Типичные формулировки:

- «Некорректный формат файла. Ожидается DICOM (.dcm / .dicom).»
- «Ожидается ZIP-архив (.zip).»
- «Файл исследования пустой.»
- «Архив пустой.»
- «Файл слишком большой. Максимальный размер - 50 МБ.»
- «В архиве нет DICOM-файлов.»
- «Папка не поддерживается. Выберите один DICOM-файл или ZIP-архив.»
- «Можно загрузить один DICOM-файл или один ZIP-архив.»

Коды ответов API: [api.md](../system/api.md).
