# Анализ задачи (каркас решения)

Источник: публичное описание задачи ЛЦТ 2026 и ответы организаторов команде. Этот файл фиксирует **что нужно решить**, не реализацию модели.

## Постановка

Построить AI-сервис оценки **качества** денситометрических исследований плотности костей (DXA, DICOM CR, аппарат GE Lunar Prodigy Advance). Постановщик — Департамент здравоохранения Москвы / Центр диагностики и телемедицины.

Сервис оценивает корректность укладки и полноту визуализации зоны интереса. Он **не** ставит клинический диагноз.

## Целевой выход

Для каждого входного DICOM-файла:

| Поле | Смысл |
| --- | --- |
| `quality_class` | `0` — корректное изображение, `1` — есть нарушение качества |
| `violation_type` | текст; несколько нарушений через `;`; пусто, если нарушений нет |
| `quality_prob` | опционально, вероятность нарушения в `[0; 1]` |

Правило агрегации качества: если хотя бы один критерий нарушения равен 1, изображение некорректно. На итоговый столбец исходной таблицы ориентироваться нельзя — были ошибки агрегации.

## Допустимые `violation_type`

Поясничный отдел позвоночника:

- Некорректная укладка
- Не выравнена ось позвоночника
- Присутствуют посторонние предметы

Проксимальный отдел бедра:

- Некорректная укладка
- Некорректная область интереса

В ТЗ упоминаются 6 критериев, фактически для метрик — 5 типов: позиционирование и ротация бедра объединены.

Macro-F1 считается по этому закрытому списку.

## Что не является целью MVP

- выявление сколиоза, переломов, эндопротеза, люмболизации как ошибок качества;
- bounding box / маски нарушений (достаточно факта нарушения);
- обязательный разбор белых полос разметки денситометра.

Опциональные преимущества (не блокер каркаса): эндопротез, подсветка зоны, анализ аппаратной разметки.

## Данные (для будущей реализации, не для этого репозитория)

- один тип аппарата; пиксельный масштаб фиксирован: X = 0.6 мм, Y = 1.05 мм;
- разметка на уровне study-папки в таблице, а выход модели — на уровне файла;
- в обучающем наборе есть дубликаты пикселей; каждый файл обрабатывается отдельно;
- тестовый набор — тот же тип исследований.

Датасет и веса **не** хранятся в этом репозитории.

## Следствия для архитектуры каркаса

1. Backend должен будет принимать пакет файлов и возвращать таблицу 1:1 с изображениями.
2. ML-сервис должен уметь различать анатомический регион (позвоночник / бедро), потому что словари нарушений разные.
3. Геометрия (см над вертелом и т.п.) переводится в пиксели фиксированным масштабом, без PixelSpacing в DICOM.
4. Проверяемость важнее хостинга: Docker Compose + README — обязательная часть решения, не «опциональный деплой».

## Этапы оценки организаторами

1. Бинарная корректность изображения.
2. Типы нарушений (отдельные и агрегированные метрики).

Ошибка в типе при верном `quality_class=1` улучшает общую метрику качества и ухудшает метрики по нарушениям.
