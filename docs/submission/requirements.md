# Соответствие задаче

Таблица для проверки BoneCheck AI по постановке ЛЦТ 2026: оценка качества исследований плотности костей. Учтены письменные ответы организаторов по полям результата, словарю нарушений и правилу «одно изображение - одна строка».

Оглавление: [README.md](../README.md).

В таблицу входят требования, которые видны в работе системы.

| Требование | Реализация в системе | Где посмотреть |
| --- | --- | --- |
| Оценка снимка моделью | В текущей версии модель не подключена. Формат результата и экраны описаны отдельно | [limitations.md](../product/limitations.md), [results.md](../product/results.md) |
| Оценивается качество укладки DXA, а не диагноз и не минеральная плотность | Назначение продукта. В шапке: «Проверка качества укладки. Не диагноз и не измерение минеральной плотности.» | [product.md](../product/product.md), интерфейс |
| Пользователь передаёт изображение и получает оценку и найденные ошибки | Загрузка DICOM или ZIP, экран результата, карточка | [scenario.md](../product/scenario.md) |
| Вход - DICOM | Принимаются `.dcm` и `.dicom` | [files.md](../product/files.md) |
| Одна строка результата соответствует одному изображению | Один DICOM - одно исследование. Каждый DICOM в ZIP - отдельное исследование. В XLSX одна строка на снимок | [files.md](../product/files.md), [api.md](../system/api.md) |
| `quality_class`: 0 - корректно, 1 - нарушение | Поле результата. На экране: «Укладка корректна» или «Нарушение качества укладки». В XLSX: «Корректно» или «Нарушение» | [results.md](../product/results.md) |
| Если нарушен хотя бы один критерий, изображение некорректно | Класс 1 требует непустой список нарушений. Класс 0 - пустой список | [results.md](../product/results.md) |
| `violation_type`: текст, несколько значений через `;`, пусто если нарушений нет | Та же строка в API, на экране и в XLSX. В истории пустая строка у готового исследования показана как «Без нарушений» | [results.md](../product/results.md) |
| `quality_prob` необязателен, диапазон от 0 до 1 | Показывается как «Вероятность нарушения» в процентах, только если значение есть | [results.md](../product/results.md), [api.md](../system/api.md) |
| Области: «Поясничный отдел позвоночника» и «Проксимальный отдел бедра» | Закрытый список. На результате критерии только этой области | [results.md](../product/results.md) |
| Сторона бедра в область не входит | Два значения области, без лево/право. Имя файла область не задаёт | [results.md](../product/results.md) |
| Поясничный отдел: «Некорректная укладка», «Не выравнена ось позвоночника», «Присутствуют посторонние предметы» | Эти формулировки на стартовом экране, в результате и в фильтре истории | [results.md](../product/results.md), экран «Анализ» |
| Бедро: «Некорректная укладка», «Некорректная область интереса» | Позиционирование и ротация объединены в «Некорректная укладка». «Некорректная область интереса» - полнота визуализации зоны | [results.md](../product/results.md) |
| Сколиоз, перелом, эндопротез и люмболизация не являются ошибкой укладки | Этих формулировок нет в типах нарушений | [limitations.md](../product/limitations.md) |
| Для метрик достаточно факта нарушения, без рамки и маски | Результат содержит факт и тип нарушения | [results.md](../product/results.md) |
| Решение запускается локально, изображения не уходят во внешний сервис | Запуск на своей машине или в Docker. Интерфейс обращается к локальному API | [running.md](../system/running.md), [architecture.md](../system/architecture.md) |
| Нужны инструкция запуска и возможность проверить результат | Команды запуска, `/health`, загрузка файла, история, XLSX | [running.md](../system/running.md), [README.md](../../README.md) |
| Репозиторий публичный, без личных паролей | https://github.com/mister-kaka/bonecheck-ai | [submission.md](submission.md) |
