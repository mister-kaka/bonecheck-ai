# Вопросы и ответы

## Какую задачу решает система?

Оценивает качество укладки DXA-снимка: можно ли использовать исследование дальше или на нём есть нарушение получения изображения.

## Для кого предназначен продукт?

Для врача-рентгенолога и сотрудника диагностического отделения. Эксперт может пройти тот же сценарий: загрузить файл и открыть результат.

## Какие входные данные поддерживаются?

Один DICOM (`.dcm` или `.dicom`) или один ZIP с такими файлами. Размер — до 50 МБ.

## Что именно анализируется?

Качество укладки поясничного отдела позвоночника или проксимального отдела бедра. Диагноз и минеральная плотность не определяются.

## Какие результаты выдаются?

Класс качества, анатомическая область, список нарушений и, если значение есть, вероятность нарушения. Рядом показывается снимок.

## Какие нарушения определяются?

Поясничный отдел: «Некорректная укладка», «Не выравнена ось позвоночника», «Присутствуют посторонние предметы».

Бедро: «Некорректная укладка», «Некорректная область интереса».

## Как обрабатываются некорректные файлы?

Файл или архив отклоняется до создания исследования. На экране заголовок «Файл не принят» и причина.

## Можно ли загрузить несколько исследований?

Да, одним ZIP. Каждый DICOM становится отдельным исследованием. Итог показывается по каждому снимку.

## Как посмотреть историю?

Раздел «История». «Мои» — загрузки этого браузера, «Все» — общая история. Строку можно отфильтровать и открыть.

## Можно ли посмотреть изображение?

Да, на результате и в карточке исследования. Масштаб меняется кнопками, колёсиком и сдвигом.

## Как получить результат в виде файла?

Кнопка «Экспорт XLSX» на результате, в карточке и в истории. Скачивается таблица с полями проверки.

## Как запустить проект?

Node.js 20 и npm: отдельно API и интерфейс. Либо `docker compose up --build` из корня репозитория. Команды: [running.md](running.md).

## Как устроена архитектура?

Интерфейс обращается к API. API хранит DICOM и метаданные исследования, выполняет проверку и отдаёт статус, результат и XLSX. Схема: [architecture.md](architecture.md).

## Как система работает с медицинскими данными?

Снимки остаются на машине, где запущен сервис. Во внешний сервис они не отправляются. В публичный репозиторий DICOM не входят.

## Какие есть ограничения?

Система не заменяет врача и не ставит диагноз. Проверяются две анатомические области. Есть лимиты размера и состава файла. Подробнее: [limitations.md](limitations.md).

## Где находится документация API?

[api.md](api.md). При запущенном API то же описание открывается на http://localhost:3000/api/docs.
