# ML-слой

Документ соответствует каталогу `ml/` и вызову модели из backend. Архитектура CNN, метрики обучения и веса здесь **не** придуманы.

Ответственный по плану команды: Кирилл (ML Lead). Состояние его работы **в этом git-репозитории** - только каркас.

### Процесс-заглушка

`ml/src/app.py`: печатает `RUEN ML service placeholder is running` и `sleep` в цикле. Нет FastAPI/Flask, нет чтения DICOM, нет загрузки весов.

### Docker

Образ `python:3.12-slim`. `requirements.txt` **не устанавливается** в образ (комментарий в Dockerfile: для placeholder достаточно stdlib). Порт 8000 объявлен, процесс его не слушает.

### Зависимости для будущего обучения

В `requirements.txt` перечислены: `torch`, `pydicom`, `opencv-python`, `numpy`, `pandas`, `scikit-learn`. Это список намерения, не доказательство, что обучение уже идёт и этими библиотеками.

### Контракт со стороны backend

Backend не ходит в Python. Есть TypeScript-интерфейс `MlClient` и `MockMlClient`.

Вход mock:

- `studyId`
- `filePath`
- `originalFileName`

Выход (поля ТЗ):

- `quality_class`
- `violation_type`
- опционально `quality_prob`
- опционально `anatomical_region`

## Ограничения из ТЗ, которые ML должен соблюсти

- локальный inference, без облачных API;
- выход на **файл**, не на папку;
- закрытый словарь `violation_type`;
- патологии (сколиоз, перелом, эндопротез) не целевые классы;
- в train разметка study-level, image-level labels нет - это блокер, а не решённая архитектура.
