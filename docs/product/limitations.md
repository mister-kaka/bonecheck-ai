# Ограничения

Границы продукта, которые важны при чтении результата и при проверке системы.

Оглавление: [README.md](../README.md).

## Оценка укладки

Проверка вызывает ML-сервис. Описание pipeline: [ml/README.md](../ml/README.md).

`site_prediction` возвращает `quality_class`, `violation_type` и `anatomical_region`. Поля `quality_prob` в этом ответе нет, процент на экране не показывается. Сторона бедра и внутренние scores в результат API не входят.

Тепловая карта — готовый PNG рядом с DICOM. Если файл не записан, текстовый результат сохраняется, а вкладка «Тепловая карта» скрыта.

Веса в git не хранятся. Без файлов в `ml/models/` процесс ML не начинает слушать порт, исследование получает статус «Ошибка анализа». API при этом продолжает работать.

Экран, история и XLSX показывают результат в формате из [results.md](results.md). Колонка вероятности в XLSX остаётся пустой.

## Медицинские

BoneCheck AI не заменяет врача. Результат - оценка качества укладки и полноты визуализации области.

Система не ставит диагноз, не описывает заболевание и не измеряет минеральную плотность кости. T-score и клиническое заключение в результат не входят.

Сколиоз, перелом, эндопротез и люмболизация не входят в типы нарушений укладки. Чёрные прямоугольники на снимке - маскирование мягких тканей, а не признак ошибки исследования.

## Области

В формате результата допустимы две области:

- поясничный отдел позвоночника;
- проксимальный отдел бедра.

Сторона бедра в результате не кодируется. Имя файла не задаёт область.

## Файлы

- один DICOM или один ZIP за загрузку;
- до 50 МБ на файл и на архив;
- в архиве не больше 30 записей и не больше 200 МБ после распаковки;
- в архиве только `.dcm` и `.dicom`;
- просмотр открывает несжатый одноканальный снимок глубиной 8 или 16 бит.

## История

«Мои» - загрузки данного браузера. Очистка данных сайта в браузере отделяет новые загрузки от прежних «Моих». Старые записи остаются в «Все».

В ZIP итог показывается по каждому снимку. В таблице и в XLSX одна строка соответствует одному снимку.
